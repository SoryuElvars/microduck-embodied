# MicroDuck model_5999 短程续训 A/B 对比

日期：2026-09-11

## 实验条件

- 起点：同一个 `model_5999.pt`
- A：继续使用原配置，不启用 symmetry
- B：只增加 mirror loss，`mirror_loss_coeff=0.5`
- 两组均为 4096 environments、seed 42、250 iterations、每 50 iterations 保存
- 部署形态评测：CPU MuJoCo + BAM M6，1 秒预热、10 秒固定指令、seeds 42–46
- 所有新评测 episode 均无跌倒，所有训练标量均为有限值

## 动作镜像诊断

| 模型 | ONNX 镜像等变 RMSE | 正负转向闭环镜像 RMSE | 正负横移闭环镜像 RMSE |
| --- | ---: | ---: | ---: |
| baseline 5999 | 0.06461 | 0.17497 | 0.26274 |
| A-6150 | 0.06052 | 0.19366 | 0.18359 |
| B-6248 | 0.04543 | 0.15482 | 0.13321 |

B 相对 baseline 将 ONNX 镜像等变 RMSE 降低约 30%，横移闭环镜像误差降低
约 49%。因此 mirror loss 确实生效；但负向原地转仍没有形成有效动作，说明
“网络更对称”没有转化为“速度指令双向可控”。

## 结论

1. A、B 都不能作为合格通用速度控制器。
2. 单纯多训练 250 iterations 会让行为在 checkpoint 间大幅切换；A-6150 的
   负转是分叉且不稳定的局部行为，不是可靠改善。
3. mirror loss 0.5 改善了网络级与横移级对称性，但没有修复负向转向，也没有
   消除前进偏航。
4. 两组都继续忽略 `vx=+0.1`，与当前 tracking reward 在小误差区过宽的判断一致。
5. 下一次应停止延长这两条 run，按单变量原则单独测试更严格的 tracking std；
   优先只收紧 angular-velocity tracking，再另行处理低速 linear tracking。
